## Base URL

Edge Functions are the primary backend API for ScreenThis. They handle security-sensitive operations including guest access, invitation delivery, video uploads, webhook processing, email sending, staff management, and data retention. All functions are mounted at the base URL below.

```bash
https://tobniuipsothugcuqhdb.supabase.co/functions/v1/<function-name>
```

<Callout kind="info">

Authentication classes: Public (no auth), Staff JWT (Supabase session), Guest JWT (short-lived token), Signed webhook (HMAC), Shared secret (header), Scheduler/internal (platform-protected).

</Callout>

## Guest Access

These endpoints power the guest video access flow: validate a code, issue a short-lived guest token, and record playback activity.

### POST `/verify-access-code`

Verify a guest access code and return the minimum video and access context needed to continue the guest flow.

**Auth:** Public  
**Rate limit:** 10 failed attempts per 15 minutes per IP

<ParamField body="code" param-type="string" required="true" show-location="false">
Guest access code entered by the recipient.
</ParamField>

```bash
curl -X POST https://tobniuipsothugcuqhdb.supabase.co/functions/v1/verify-access-code \
  -H "Content-Type: application/json" \
  -d '{"code":"ABC123"}'
```

Returns an array of matching rows with fields including `video_id`, `title`, `description`, `poster_url`, `duration`, `gumlet_asset_id`, `views_remaining`, `expires_at`, and `access_code_id`.

<Callout kind="info">

Returns `400` with `error_code` values `NOT_YET_AVAILABLE` or `EXPIRED` when the code is outside its valid access window. Returns `404` for an unknown code and `429` when the rate limit is exceeded.

</Callout>

### POST `/generate-guest-token`

Generate a short-lived guest JWT after the server validates the access code, expiry window, and remaining views.

**Auth:** Public

<ParamField body="access_code_id" param-type="string" required="true" show-location="false">
Unique ID of the validated access code.
</ParamField>

```bash
curl -X POST https://tobniuipsothugcuqhdb.supabase.co/functions/v1/generate-guest-token \
  -H "Content-Type: application/json" \
  -d '{"access_code_id":"8e2f9d8b-2b8d-4f85-a6d7-6c6d6a4f4c21"}'
```

The function atomically increments `views_used` and enforces a 10-second issuance cooldown for the same code.

### POST `/log-guest-viewing-event`

Log guest playback events after the client has a guest JWT.

**Auth:** Guest JWT

<ParamField body="video_id" param-type="string" required="true" show-location="false">
Video ID associated with the active guest session.
</ParamField>

<ParamField body="event_type" param-type="string" required="true" enum="access,start" show-location="false">
Guest event to record.
</ParamField>

<ParamField body="device" param-type="string" required="true" show-location="false">
User agent or device description captured by the client.
</ParamField>

```bash
curl -X POST https://tobniuipsothugcuqhdb.supabase.co/functions/v1/log-guest-viewing-event \
  -H "Authorization: Bearer guest_jwt_example_9xmk7q2r" \
  -H "Content-Type: application/json" \
  -d '{"video_id":"0d7a8b9e-9e2e-4a6d-b3c1-7bbf7a2274b1","event_type":"start","device":"Mozilla/5.0"}'
```

A successful response returns `success: true` and the updated `views_remaining` count.

## Invitations

Invitation endpoints create, resend, and revoke guest access codes. These endpoints require a Supabase access token from the active staff session.

### POST `/create-access-code`

Create an access code, persist the invitation, and send the guest email.

**Auth:** Staff JWT

<ParamField body="video_id" param-type="string" required="true" show-location="false">
Target video UUID.
</ParamField>

<ParamField body="guest_email" param-type="string" required="true" show-location="false">
Guest email address. The server normalizes the address before sending.
</ParamField>

<ParamField body="expires_at" param-type="string" required="true" show-location="false">
ISO 8601 timestamp when the access code expires.
</ParamField>

<ParamField body="views_allowed" param-type="integer" required="false" show-location="false">
Optional limit on how many times the guest can generate a viewing session.
</ParamField>

<ParamField body="starts_at" param-type="string" required="false" show-location="false">
Optional ISO 8601 timestamp before which the code is not yet valid.
</ParamField>

<ParamField body="display_timezone" param-type="string" required="false" show-location="false">
Timezone label used when presenting the invitation window to recipients.
</ParamField>

<ParamField body="video_title" param-type="string" required="false" show-location="false">
Template context value for the email body. The authoritative video record is still loaded server-side.
</ParamField>

<ParamField body="base_url" param-type="string" required="false" show-location="false">
App origin used to build links in the email.
</ParamField>

<ParamField body="email_template" param-type="string" required="false" show-location="false">
Optional rendered invitation template body.
</ParamField>

<ParamField body="job_item_id" param-type="string" required="false" show-location="false">
Bulk job item identifier used for idempotent batch sends.
</ParamField>

```bash
curl -X POST https://tobniuipsothugcuqhdb.supabase.co/functions/v1/create-access-code \
  -H "Authorization: Bearer supabase_access_token_example_9xmk7q2r" \
  -H "Content-Type: application/json" \
  -d '{"video_id":"0d7a8b9e-9e2e-4a6d-b3c1-7bbf7a2274b1","guest_email":"jane.chen@acme.com","expires_at":"2026-01-01T23:59:59Z","views_allowed":3,"starts_at":"2025-12-15T08:00:00Z","display_timezone":"America/Los_Angeles","video_title":"Q4 Product Walkthrough","base_url":"https://app.screenthis.com"}'
```

A successful response returns `success`, the created `accessCode`, and an `email` object with provider delivery metadata.

Upload endpoints register videos, initialize direct uploads, and manage the archived or deleted state of video records and provider assets.

Register a video and trigger the automation workflow for URL-based ingest.

<ParamField body="video_url" param-type="string" required="true" show-location="false">

</ParamField>

<ParamField body="poster_url" param-type="string" required="false" show-location="false">

</ParamField>

<ParamField body="duration_seconds" param-type="integer" required="true" show-location="false">

## Webhooks

Webhook endpoints are invoked by external systems or internal automation. Signature validation and shared-secret checks are part of the contract for these functions.

### POST `/gumlet-webhook`

Receive Gumlet asset status updates and apply them to matching videos.

**Auth:** Signed webhook via `x-gumlet-signature`

```bash
curl -X POST https://tobniuipsothugcuqhdb.supabase.co/functions/v1/gumlet-webhook \
  -H "x-gumlet-signature: hmac_sha256_example_9xmk7q2r" \
  -H "Content-Type: application/json" \
  -d '{"data":{"asset_id":"ast_7vK2mLp9Qe","status":"ready"}}'
```

The signature must match the HMAC-SHA256 digest of the raw request body using the configured webhook secret.

### POST `/pabbly-update-video-status`

Update video status from the automation layer.

**Auth:** Shared secret via `x-pabbly-secret`

<ParamField body="video_id" param-type="string" required="false" show-location="false">
Target video UUID. Required when `set_gumlet_asset_id` is present.
</ParamField>

<ParamField body="gumlet_asset_id" param-type="string" required="false" show-location="false">
Provider asset ID used when the workflow identifies a video by asset instead of UUID.
</ParamField>

<ParamField body="status" param-type="string" required="false" show-location="false">
New video status such as `pending`, `processing`, `ready`, or `failed`.
</ParamField>

<ParamField body="duration" param-type="integer" required="false" show-location="false">
Duration to persist on the video record.
</ParamField>

<ParamField body="set_gumlet_asset_id" param-type="string" required="false" show-location="false">
Provider asset ID to attach to the video record.
</ParamField>

```bash
curl -X POST https://tobniuipsothugcuqhdb.supabase.co/functions/v1/pabbly-update-video-status \
  -H "x-pabbly-secret: pabbly_secret_example_9xmk7q2r" \
  -H "Content-Type: application/json" \
  -d '{"video_id":"0d7a8b9e-9e2e-4a6d-b3c1-7bbf7a2274b1","status":"ready","duration":742}'
```

Provide at least one identifier, either `video_id` or `gumlet_asset_id`, and at least one update field.

```bash
  -H "svix-timestamp: 1736035200" \
  -H "svix-signature: v1,hmac_example_9xmk7q2r" \
  -H "Content-Type: application/json" \
  -d '{"type":"email.delivered","data":{"email_id":"re_7c2ab91dfc6f4f71","to":["jane.chen@acme.com"]}}'
```

The function accepts supported delivery events, records normalized status changes, and returns `ok: true`.

## PostgREST & RPC

The browser also directly accesses RLS-protected tables via Supabase PostgREST and calls client-facing RPC functions such as `get_access_codes_with_details`, `get_analytics_summary_for_user`, `get_database_health_metrics`, and `admin_update_profile`. These are not Edge Function HTTP endpoints. Call them through the Supabase JavaScript client query builder rather than `/functions/v1`.
