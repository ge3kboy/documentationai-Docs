## Tech stack at a glance

ScreenThis is built as a Vite + React single-page application with a Supabase backend. The stack prioritizes type safety, tenant isolation, and security-sensitive operations on the server side.

## Frontend

The frontend is a client-rendered SPA built around React, TypeScript, and a lightweight routing and state-management layer. UI composition relies on accessible primitives, utility-first styling, and a small set of focused libraries for animation, charts, and icons.

## Backend & Data

Supabase provides the application backend, including the PostgreSQL database, authentication, and Edge Functions. The backend enforces tenant boundaries with Row Level Security and keeps privileged operations out of the browser.

  <Card title="Supabase" href="#" icon="server" horizontal="false">

## Video & Integrations

Video delivery and workflow automation are handled by external services, with ScreenThis coordinating them through server-side functions and callbacks. This keeps ingest, playback, and provider status changes within a controlled integration layer.

## Email

Transactional email flows run through a dedicated provider rather than directly from the client. Invitation delivery, notifications, and related email actions are triggered from Edge Functions.

## Hosting

The frontend deploys as a Vite-built SPA on Vercel. Build and deployment stay separate from backend execution, which continues to run through Supabase services.

## Key conventions

A few architectural conventions shape how the codebase is organized and how security decisions are made. These conventions matter more than the library list because they affect routing, data access, and authentication boundaries.

<Callout kind="info">
ScreenThis uses a multi-tenant company model with company-scoped settings. Guest access does not use Supabase Auth — it uses a custom, short-lived guest JWT signed with a separate secret.
</Callout>
